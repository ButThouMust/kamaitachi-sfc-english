Pointer data from $258000-$258491
Each ID consists of a structure of 9 bytes, three 24-bit pointers to data.
For example, ID 0 consists of the data [92 84 25 55 D2 25 B1 84 25].

For some reason, each ID's pointers are in the order [palette, tilemap, tiles],
but the order for the data itself in the ROM is [palette, tiles, tilemap].

Tilemaps are all assumed to be 0x20 tiles wide and 0x1C tiles tall.
Tilesets are all assumed to be in 4bpp SNES format once decompressed.

According to my graphics dumper, the tilemap data for the last entry ends at
0x245081 ($48D081). So all in all, graphics from 0x128492 to 0x245081, or
0x11CBF0 bytes (over a megabyte!).

--------------------------------------------------------------------------------

Format for palettes:
The byte at the pointer contains up to 8 bits for how to interpret data.
Read bits starting from the MSB, and ignore trailing 0 bits at the end.
Data gets copied into a buffer at $7FF700, X-indexed.
- If 1, advance X offset by 2 (color 0 in row is black), and read a group of
  0x1E bytes (0xF groups of 2 byte color values) into the buffer.
- If 0, advance X offset by 0x20 = skip the row of colors.

The tilemaps and tilesets are each compressed in their own formats. They were
complicated enough to deserve their own writeups about how they work.

--------------------------------------------------------------------------------

There is one special case with tilemaps, and one special case with palettes.

The pointer value of the file select bookmark's tilemap is $4640AF. That it
doesn't map to ROM marks that the pointer is for TWO compressed tilemap blocks:
first for the currently selected bookmark, which is in its own gfx layer on top
of the second tilemap, which is for the three bookmarks in the background. The
second block starts immediately after the end of the first block.

The game colors in bookmarks based on the player's progress in the file, but
this doesn't substantially change the graphics themselves. There are two pointer
tables at $018225 and $018232 for blocks of palette data: brown at $01E780, pink
at $01E79E, gold at $01E7BC, and three more at $01E7DA, $01E7F8, $01E816.

---

Specifically, there are two "animation frames," so to speak, that solely consist
of changing five colors at a time in the layer's palette. It accomplishes the
blood splatter effect you see. The five colors are from a table at $0094E9.

Similarly, the palettes for the title logo itself get changed on the fly.
$0094A9: 0x10 color table for title screen background
$0094e9: 0x 5 color table for splatter frame 1
$0094f3: 0x10 color table for fully red palette of blood splatter
$009513: 0x10 color table for final palette visible on screen

--------------------------------------------------------------------------------

The tilesets for some of the labyrinth pathways (gfx IDs 4D-51) all use common
graphics data. You can reuse tileset 50 for IDs 4D-51.

4D is a subset of 4E (first 4 tiles of 5).
4E is identical to 4F and 51.
4E is a subset of 50 (first 5 tiles of 6).

Bear in mind, the tilesets are not very large to begin with, and you save less
than 200 bytes total from cutting out and repointing tilesets 4D-4F and 51.

--------------------------------------------------------------------------------

The palettes for ALL of the labyrinth pathways (4D-57) are identical, so 0xA are
duplicates. Other gfx ID groups with the same palettes:
- 2A-2B, 1 duplicate;  guest room with curtains open/closed
- 59-5A, 1 duplicate;  door 6 in labyrinth
- 68-6D, 5 duplicates; banana dismemberment joke
- 6F-70, 1 duplicate;  buzzsaw animation
- 71-78, 7 duplicates; frames of the laser firing animation
- 79-7B, 2 duplicates; pictures explaining how the window shattered

Save 0x1F*(A+1+1+5+1+7+2) bytes.
